# FPGA architecture descriptions

`ice40-up5k/` describes the Lattice iCE40UP5K in the SG48 package, the FPGA
on the iCESugar board. `ice40-lp1k/` describes the iCE40LP1K in the CM36
package, the FPGA on the iCESugar-nano: the board on Amy's desk, whose
iCELink firmware reports itself as the iCESugar-nano's. It is generated by `sv/examples/ice40_arch.rs` from
the code in `sv/src/arch/ice40/`. That code is a module of epitome-sv rather
than a separate tool, so that epitome-sv can use the description and the
bitstream packer directly when it targets the part.

```bash
cargo run --release -p epitome-sv --example ice40_arch
```

It does every part in `PARTS` (`--part ice40-lp1k` does one). For each, it
reruns every source it can find and replays the records of the rest
(`--replay` replays all of them). Then it writes the description. The
same code serves both parts; only the part table (`PARTS` in
`sv/src/arch/ice40/mod.rs`) differs.

Each part's directory holds:

| File | What it holds |
|---|---|
| `record-icepack.txt` | what the `icepack` experiments found |
| `record-chipdb.txt` | what is taken from IceStorm's `chipdb-5k.txt`, in a compact form |
| `record-icebox.txt` | what the `icebox_vlog` and `icebox_explain` experiments found |
| `description.json` | the description: every fact, marked with its source, plus the cross-checks and coverage |
| `logic_cell.sv` | a SystemVerilog model of a logic cell, built from the icebox statements |
| `record-board.txt` | (LP1K only) what the iCESugar-nano did in each board experiment |

The tests are in `sv/tests/ice40_arch.rs`:

```bash
cargo test --release -p epitome-sv --test ice40_arch
```

The tests that need a tool skip it when it is missing. Set
`ICE40_REQUIRE_TOOLS=1` to make a missing tool a failure. The test that
reprograms the board runs only with `ICE40_BOARD=1`.

## Sources, and how each fact was found

The work started as a clean room: IceStorm's, nextpnr's and Yosys's source,
chip databases and documentation were not to be read. Amy then agreed
(2026-11-14) to take a look at the chip database, a data file. So the
description has four sources, and each part of it is marked with one:

- **experiment**: IceStorm's `icepack`, run as a black box. It is the pinned
  build that `sv/tools/ice40_asc_check.py --install-only` makes. Its source
  was not read. See `experiment.rs`.
- **icebox**: IceStorm's `icebox_vlog` (`.asc` to Verilog) and
  `icebox_explain`, run as black boxes from the same pinned checkout. Only
  their output is read; a traceback would print source, so stderr is
  discarded. See `icebox.rs`.
- **chipdb**: IceStorm's chip database, a data file. It is made by running
  `icebox_chipdb` from the pinned checkout as a black box (`-5` for the
  UP5K, no flag for the 1k), and only its output is read: no source, no
  documentation. See `chipdb.rs`. For the UP5K that output is byte for
  byte the `chipdb-5k.txt` that ships in YosysHQ's OSS CAD Suite, the file
  Amy agreed to. A copy of the suite was downloaded and then deleted
  without any of it being run.
- **datasheet**: Lattice's *iCE40 UltraPlus Family Data Sheet*
  (FPGA-DS-02008) for the UP5K, and the *iCE40 LP/HX Family Data Sheet*
  (FPGA-DS-02029) for the LP1K, Table 1.1 and section 2. They give the
  resource counts and what each kind of block is.

### What the icepack experiments found

Each experiment packs `.asc` text through `icepack`'s stdin and stdout and
reads the bitstream. All of them are in `experiment.rs`. The numbers below
are the UP5K's.

For the LP1K:
- the die is 14 x 18 tiles, 248 in all, with I/O tiles on all four edges;
- there are four CRAM banks of 144 lines of 332 bits, and 16 block RAMs;
- the tiles fall into 20 layouts, because I/O tiles on the bottom and side
  edges share a bank but have different layouts;
- the framing, CRC, options and comment are the same as the UP5K's.

- **Grid**: `icepack -u` of a one-tile design lists every tile. The die is
  26 x 32 tiles, 828 in all: 660 logic, 48 io, 30 ramb, 30 ramt, 8 each of
  dsp0 to dsp3, and 28 ipcon. Every tile is 16 rows; logic, dsp and ipcon
  tiles are 54 columns wide, io tiles 18, and ram tiles 42. An `.asc` with
  no tile at all makes `icepack` fail.
- **Framing**: after an optional comment and the preamble `7e aa 99 7e`,
  each command is one byte, whose high nibble is the command and whose low
  nibble is the length of its argument. Commands 6, 7 and 8 set the width,
  height and first line of the next data; command 1 selects a bank; `01 01`
  and `01 03` are followed by CRAM or block RAM data and then two zero
  bytes. Reading every bitstream this way consumes it exactly.
- **Options**: `-s` flips bit 0 of command 9's argument, `-mN` sets command
  5's argument to N, and `-n` drops the block RAM data commands.
- **CRC**: CRC-16, polynomial 0x1021, initial value 0xffff, MSB first. It
  covers the bytes after `01 05`, up to and including the `22` of the CRC
  command. This was found by searching every command boundary, two
  polynomials and two initial values; exactly one combination fits every
  bitstream tried.
- **Comment**: `ff 00`, then each line followed by `00`, then `00 ff`.
- **CRAM**: four banks of 692 bits per line, with 336, 176, 336 and 176
  lines; banks 0 and 1 hold the left half of the die, banks 2 and 3 the
  right. Each of the 676,224 tile bits was located with 40 bitstreams: the
  bits are numbered, and for each bit of that number two configurations
  are packed, one with the bits where it is 1 and one with the bits where
  it is 0. Every tile bit lands on exactly one CRAM bit. A tile is a
  `rows` x `cols` layout at an origin, and all tiles of a kind in a bank
  share the layout (36 layouts). 32,384 CRAM bits belong to no tile.
- **Block RAM**: banks of 256 lines, 160 or 80 bits wide. Word w of an EBR
  is on line w, at a fixed 16-bit column per EBR, found the same way.
- **Extra bits**: `.extra_bit B P L` sets bank B, line L, position P, and
  `icepack -u` gives back the ones outside tiles.
- **Fingerprints**: 16 random configurations. Epitome's own packer
  (`bitstream.rs`) makes the same bytes as `icepack` for each, and their
  lengths and hashes are kept, so the packer can be checked without
  `icepack`.

### What the icebox experiments found

These experiments route one logic cell of tile (8, 1) to package pins
(routes found by a search of the chipdb's switches). Then they set bits and
read what `icebox_vlog` prints.

- **LUT**: each of a cell's 20 bits, set alone. 16 of them each make the
  LUT true for exactly one input value; that value is the bit's LUT index,
  with index i = in_0 + 2 in_1 + 4 in_2 + 8 in_3. All 8 cells were tried.
- **Options**: `icebox_explain` names the other 4 bits: `CarryEnable`,
  `DffEnable`, `Set_NoReset` and `AsyncSetReset`.
- **Flip-flop**: the Verilog statement for each setting of `Set_NoReset`,
  `AsyncSetReset` and the tile's `NegClk`. The flip-flop is enabled by
  `cen`. Set/reset `sr` is synchronous unless `AsyncSetReset` is set; it
  sets the flip-flop to 1 with `Set_NoReset` and to 0 without it. `NegClk`
  clocks on the falling edge.
- **Carry**: `co = (in_1 & in_2) | ((in_1 | in_2) & ci)`. `CarryInSet`
  makes the first cell's carry in 1.
- **I/O cell**: one I/O cell on the top edge has every port wired. For each
  of the 64 settings of its `PINTYPE_0..5` bits, `icebox_vlog`'s statements
  for it are recorded, with its nets named by port. The table is the same
  for both parts. It covers plain, registered and latched inputs, the DDR
  input, and plain, registered, DDR, inverted and tristate outputs (the
  output enable plain or registered). `PINTYPE_0` alone is a plain input;
  `PINTYPE_3` and `PINTYPE_4` make a plain output.
- **Block RAM**: one RAM has its ports wired, in three groups because there
  is not enough local routing for all of them at once. `icebox_vlog`
  renders the RAM as Lattice's `SB_RAM40_4K`, with nothing set and then
  with each `RamConfig`/`RamCascade` function alone:
  - `CBIT_1:CBIT_0` is `WRITE_MODE` and `CBIT_3:CBIT_2` is `READ_MODE`.
    Lattice's documentation gives the meaning of those parameters (256x16,
    512x8, 1024x4, 2048x2).
  - The cascade bits change nothing vlog shows.
  - On the LP1K a set `PowerUp` removes the RAM. On the UP5K the RAM is
    there only with `PowerUp` set.
  - Each port bit's net and each unrouted port's value are recorded:
    `RE`, `WE`, the addresses, data and mask read 0, and the clock enables
    read 1.

### What the board showed

The board is an iCESugar-nano on Amy's desk. `icesprog -p` reports
"iCESugar-Nano" with a W25Q32 flash. The experiments are in `board.rs` and
are run with:

```bash
cargo run --release -p epitome-sv --example ice40_board
```

**Method.** Each experiment is a design made from this description, packed
by Epitome's own packer, and written to the flash with MuseLab's
`icesprog`. `icesprog` is built from source (`Icesprog::install`) and run
only as a black box, over the iCELink's USB HID interface. Copying to the
iCELink's USB drive hung macOS's FAT driver twice, so the drive is not
used.

**Wiring.** The board's schematic and pin file give the wiring:
- the iCELink's UART transmit drives A3;
- B3 goes to the iCELink's UART receive;
- D1 carries the iCELink's 12 MHz clock;
- B6 drives the LED.

So the FPGA only ever drives B3. Each design makes B3 a function of A3,
through the logic under test. The Mac sends 64 bytes at 115200 baud over the
iCELink's serial port and looks at what comes back: an echo, silence, or
other bytes.

`record-board.txt` holds 47 experiments. Each one's bitstream hash is
recorded, so `board_record_agrees` can check that the description still
makes the same designs. All twelve findings in the description's `board`
section held:
- Each of the 8 logic cells' LUTs, and each of their 4 inputs, is where the
  description says.
- An unrouted LUT input reads 0.
- Setting `IoCtrl.IE` turns a pin's input off; `REN` does not stop a driven
  input.
- A global network reaches a tile only through its column buffer, which
  needs `ColBufCtrl` set in the tile the chipdb's `colbuf` names. Without
  it, a flip-flop never clocks.
- The flip-flop clocks from D1 through global network 1, with
  `padin_glb_netwk.1` set, on either edge.
- An unrouted clock enable reads 1, and an unrouted set/reset reads 0.
- The carry formula holds: with `CarryInSet` the first cell's carry in
  is 1, and without it, 0.
- A block RAM reads its `.ram_data` contents: word 1 is read at RADDR[0] =
  A3, clocked from D1, with `RE` driven to 1. Each `RDATA` bit is the
  word's bit of the same number.
- `PowerUp` set turns the LP1K's RAM off, and an unrouted `RE` reads 0, as
  icebox_vlog says.
- The write port works: A3 is written into word 0 every clock and read
  back. `MASK[0]` set stops that bit being written; unrouted, it reads 0.

## Coverage

The JSON's `coverage` and `checks` sections hold the exact numbers for each
part. Everything below is for the UP5K unless it says otherwise. All the
checks pass, for both parts:

- The datasheet's counts match: 5,280 LUTs, 30 EBRs, 4 SPRAMs, 8 MAC16s, 1
  PLL, 2 I2C, 2 SPI, HFOSC, LFOSC, the RGB driver, and 39 I/O on SG48.
- The chipdb's grid and tiles are the experiments'.
- Every chipdb tile bit lies inside the experiments' tiles.
- The chipdb's 8 extra bits (the global networks' pad inputs) are among the
  CRAM bits the experiments found in no tile.
- Each cell's LUT and option bits are the chipdb's `LC_k` bits.

**Mapped by experiment**

- The tile grid.
- The whole bitstream format.
- Where every tile bit and block RAM bit goes.
- The packer and unpacker.
- The logic cell: the order of its LUT bits, its flip-flop options and its
  carry.

**Taken from the chipdb, with checks against the experiments**

- **Tile functions**: every tile kind's non-routing settings, by IceStorm's
  names. These cover IO pin types and controls, RAM configuration, the DSP
  and PLL settings, column buffer controls, `NegClk` and `CarryInSet`.
- **Pin map**: SG48 package pin to IO tile and PIO, for 39 pins (and the
  UWG30 package's 21).
- **Global networks**: the 8 global networks' sources (`gbufin` and
  `gbufpin`), their pad-input bits, column buffers, IO latch and IE/REN
  pairs.
- **Special cells** (26): the 8 MAC16s, 4 SPRAMs, PLL, HFOSC, LFOSC, 2 I2C,
  2 SPI, the RGB driver, LEDDA_IP, 2 IO_I3C, 2 FILTER_50NS and WARMBOOT,
  each with its ports.
- **Routing**: all 103,383 nets and 201,460 switches. Each tile's switches
  fall into one of 32 switch boxes. Each net is one of 992 shapes, placed
  by rectangles. `Routing::expand` gives the chipdb's nets and switches
  back exactly, which a test checks.

**The LP1K** has the same coverage, at its own size:
- 1,280 LUTs and 16 block RAMs, as its datasheet says;
- 27,682 nets and 53,808 switches in 37 switch boxes;
- CM36 package pins mapped to PIOs for 25 pins;
- a PLL and WARMBOOT;
- logic cell experiments that find the same bits and statements as on the
  UP5K.

**Not mapped**

- 32,376 CRAM bits outside tiles that nothing names.
- Tile bits with no function or switch: 57 per logic tile, for example. The
  JSON lists each kind.
- The DSP (UP5K only) and PLL settings, which are only named. The LP1K's
  PLL is not in its CM36 package; the chipdb lists CM36 under the PLL's
  `LOCKED` packages. The RAM modes other than 256x16, and the RAM cascade
  bits, are recorded from icebox but not tried on the board.
- The routing has not been checked against the device. The only
  black-box evidence for it is that the routes the icebox experiments
  built read back as intended.
- The full-size iCESugar (UP5K) has not been tried on a board. Only the
  iCESugar-nano's LP1K has.
- Timing.
